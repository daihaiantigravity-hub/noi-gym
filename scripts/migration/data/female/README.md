# MuscleWiki female exercise capture

This directory contains the captured female dataset, the pre-import baseline, and the live upload audit. The source male JSON files and existing male exercise content were preserved during the female upload.

- `browser-capture.json`: observed female listing pages, exercise cards, instructions, and video URLs.
- `scope-capture.json`: observed Joints and equipment-filtered listing pages, with source root and pagination status.
- `musclewiki-female-import.json`: all records with an observed female video, deduplicated by canonical exercise URL. Some records still lack category or primary muscle metadata.
- `musclewiki-female-pilot.json`: five complete records for a small review batch: Dumbbell Curl, Dumbbell Bench Press, Bodyweight Squat, Barbell Squat, and Kettlebell Swing.
- `coverage-report.json`: counts, integrity check against the male-file baseline, and source listing discrepancies.
- `merge-readiness.json`: pre-upload read-only reconciliation against the exercise table. It is a historical plan, not the current database state.
- `video-resolutions.json`: three reviewed front/side selections where the source exposed two competing video pairs; the excluded URLs remain in each import record's `video_resolution` provenance.
- `unresolved-metadata.json` and `without-female-video.json`: items requiring further review.
- `audit-before.json`, `database-before.json`, `local-inventory.json`, `male-files-sha256.json`: read-only baseline snapshots from before the female capture.
- `upload-events.jsonl` and `upload-audit.json`: resumable upload log and post-upload reconciliation with Supabase Storage and the pre-import male baseline.
- `publish-plan.json`: reviewed mapping for the 242 new rows, including category and browse-group provenance and Advanced/Joints links.

Regenerate the derived capture files with `node scripts/migration/prepare-musclewiki-female.mjs` from the repository root. It checks the hash of every original male dataset file and aborts if any changed. Use `node scripts/migration/audit-musclewiki-female-upload.mjs` to refresh the current Supabase reconciliation. `plan-musclewiki-female-merge.mjs --live` was used before upload and should not replace the post-upload audit.

Do **not** pass these JSON files to `scripts/seed-exercises.mjs`: that script sets every imported row to Draft, including previously Published rows. Do **not** use `scripts/migration/upload-musclewiki-media.mjs` for female videos: its storage path omits gender and can overwrite male objects. Use the female-specific uploader for retries.

The captured female `videos[].url` values are source URLs under `https://musclewiki.com/api-next/videos/`. A HEAD request to a sample URL on 2026-09-29 returned HTTP 200 with `video/mp4` through Cloudflare and no redirect. This establishes the public delivery endpoint, **not** where the original video file is physically stored. Before upload, a read-only check found 1,698 MuscleWiki exercise rows with 3,396 male media entries, of which 3,370 had video URLs on this project's Supabase Storage and 26 had no video URL. There were no female media entries at that time.

The [MuscleWiki API terms](https://api.musclewiki.com/api-terms) restrict downloading and re-hosting API media. They should not be used as proof of the physical hosting location or, without further review, as a conclusion about the separate `musclewiki.com/api-next/videos/` endpoint. The [main website terms](https://musclewiki.com/terms) govern reuse of website content; the project's deployment should satisfy the applicable branding, link, and usage-right conditions.

`node scripts/migration/upload-musclewiki-female.mjs` performs a read-only dry run; add `--apply` to upload or retry. It uploads to `exercise-media/exercises/musclewiki/female/<source-id>-<angle>.mp4`, appends female media to existing rows while preserving other media and status, and creates source-only exercises as Draft for admin review. The upload is resumable: existing female media is skipped and an object uploaded before a failed database update is reused. `--dataset`, `--offset`, `--limit`, and `--concurrency` allow smaller batches. Errors and progress go to `upload-events.jsonl` in this directory. Female Storage paths are saved with an empty `videoUrl` in the database, and the current admin code derives their Supabase public URLs for editing and preview. This keeps existing deployed public pages from displaying female videos before a deliberate gender selector is added. The bulk importer accepts original source clips up to 32 MB and 60 seconds; the admin form still limits manual uploads to 25 MB and 15 seconds.

The source's listing counts are inconsistent with unique observed exercise URLs for eight unfiltered muscle categories and 53 equipment-filtered collections. Every affected equipment collection has a complete pagination chain and the expected number of cards, but some cards repeat exercise URLs. See `coverage-report.json` for exact differences; the capture should not be described as exhaustive until those discrepancies are resolved. Equipment observed through a filtered source listing is marked with `category_source: "source-equipment-listing"`; a filename-only inference is marked `female-media-filename`. Recovery and Vitruvian have no corresponding project category and remain unresolved. `listed_in` and `joint_targets` are source listing memberships, not anatomical primary muscles.

## Capture scope

The browser pass followed the unfiltered female `?model=f` listings for all 48 browse-by-muscle categories. These include all 23 Advanced target slugs defined in `lib/exercises/targets.ts`, but eight source counts still differ from unique URLs. A second pass traversed all six Joints `/recovery` listings and assessed 816 muscle-by-equipment routes across 17 source filter slugs. The Joints listings are verified against source counts and yielded 43 unique exercises, 22 of which were absent from the unfiltered capture. Of the equipment routes, 676 match source counts, 53 have duplicate-card count discrepancies, 47 Recovery routes returned 404, and 40 Cardio routes are marked `alias-inferred` based on identical result sets observed for eight representative muscles rather than individual traversal. `scope-capture.json` and `coverage-report.json` retain these distinctions.

The combined source dataset contains 1,938 exercises with 3,876 selected female videos. Eight captured exercise URLs have no qualifying female video. All imported records have instructions; the capture itself still lacks independently verified primary-muscle values for 375 records. At the upload step, all 1,938 source exercises had database rows, including 242 new Drafts. All 242 new rows are now Published, with source-listing browse groups and supported equipment categories. The current audit finds 3,864 female videos linked to exactly 3,864 Storage objects. The remaining 12 source video URLs return HTTP 404. They are listed by exercise and angle in `upload-audit.json`; no unverified substitute was added. The audit found no changes to the baseline rows' status, metadata, or non-female media.

## Merge readiness

The pre-upload read-only reconciliation found 1,696 matching Published rows. The three competing source video pairs were resolved in `video-resolutions.json` using the observed filtered listing, equipment label, and full URL slug. The 242 new exercise URLs lacked verified primary-muscle metadata, so they were initially created as Draft. On 2026-09-29, `publish-musclewiki-female.mjs --apply` published all 242 after checking their uploaded front/side videos, instructions, difficulty, and source listing provenance. Of those, 233 use standard source listing membership for browse groups, eight use an Advanced listing, and one wrist-only exercise has no claimed primary muscle and is reached through its Joint target. The 116 Recovery and 22 Vitruvian categories were identified from their source video filenames and added as project categories; 48 Advanced/Joints links were added. Listing membership is used for browsing, not as independently verified anatomical primary-muscle data. The public UI prefers existing male videos when present and displays female videos for female-only exercises. The video-angle parser reads the angle at the end of the filename, after exercise-name words such as “front squat” or “side bend”; this prevents a silent angle mix-up.

The configured MuscleWiki API key returned HTTP 403 (`Invalid or expired API key`) on the read-only female exercise request checked on 2026-09-29. This blocks verification of API streaming with the current key, but does not block reading the staged source URLs: the sampled `musclewiki.com/api-next/videos/` URL responded to an unauthenticated HEAD request. It does not itself authorize copying that media into Supabase Storage.
